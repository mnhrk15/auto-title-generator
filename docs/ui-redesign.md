# UI 刷新計画(AI 臭いデザインの除去 + UI/UX 改善)

> 進捗: PR ① 不具合の修正 … 対応済み / PR ② 見た目の作り直し … 未着手 / PR ③ 使い勝手の改善 … 未着手

## Context
現在の画面には、AI が作った画面によくある特徴が一通り揃っている。
- 紫と青のグラデーション 17 箇所、ガラス風の半透明、常時ループするアニメーション 10 個、`box-shadow` 50 行、角丸 64 箇所、Font Awesome のアイコン 40 種類以上。
- `style.css` は 3009 行あり、同じセレクタのベース定義が最大 5 重に重なっている。

使い勝手にも問題がある。
- 進捗表示は、約 30 秒で 99% に達したあと、最大 1 分以上止まって見える。
- 通知の出る場所が 5 か所に分かれている。
- 結果は 6 件ずつのページ送りで、見比べにくい。
- 日本語変換を確定する Enter で生成が始まってしまう。

これらを解消し、道具として落ち着いて使える画面にする。

**ユーザーと決めた方針**
- 配色は今の青テーマを残し、装飾だけを削る。特集で使っている紫と金も青系にそろえる。
- Font Awesome は読み込みをやめる。意味のあるアイコンだけインライン SVG で描く。
- `style.css` は新しく書き直す。
- PR は 3 つに分ける。①不具合の修正 → ②見た目の作り直し → ③使い勝手の改善。
- 結果はページ送りをやめ、画面幅に応じたグリッドで全件を並べる。
- 待ち時間は % 表示をやめ、経過秒数と所要時間の目安を出す。中止ボタンを付け、待っている間も前回の結果を残す。
- コピーしたことは、押したボタンの表示だけで知らせる。画面下中央の表示はやめる。

進め方はグローバル指針に従う。各 PR に着手する前に、その PR の詳細設計(画面の文言、変更するファイル)を短く提示して合意を取る。設計はこのファイルに残す。

## PR ①:不具合の修正(小さい)

(この文書の行番号は、計画を立てた時点の main のもの)
ブランチ: `fix/ui-bugs`

1. **日本語変換中の Enter で送信される**
   - 場所: `app/static/js/generate.js:121-129` の keydown ハンドラ
   - 対応: `e.isComposing || e.keyCode === 229` のときは何もしない。
2. **特集と関係のないエラーでも特集の案内バナーが出る**
   - 場所: `generate.js:110-112`
   - 対応: バナーは `FEATURED_KEYWORDS_ERROR` のときだけ出す。この分岐は `handleApiError` 側にすでにあるので、それ以外の経路から出している箇所を削る。
3. **上限ちょうど(30/30 など)で文字数が赤くなる**
   - 場所: `template-card.js:23-49`
   - 対応: error 表示の条件を `>= max` から `> max` に変える。
4. **完了ステップのチェックが表示されない**
   - 原因: `style.css:629` が `'Font Awesome 5 Free'` を指定している。
   - 対応: PR ② で CSS を書き直すと自然に消えるので、PR ① では 6 に変えるだけにする。
5. **生成エラーが 5 秒で消える**
   - 場所: `status.js:5,27`
   - 対応: 自動で消すのをやめ、次の操作(再生成、入力の変更)で消す。

確認: pytest と ruff を通す。ブラウザで次を確かめる。IME で変換を確定しても送信されないこと、30 文字ちょうどのカウンタの色、エラーが表示されたまま残ること。

## PR ②:見た目の作り直し(最大)
ブランチ: `feat/ui-redesign-visual`

### デザインの基準(`:root` のトークン)
- **色**
  - 青は 1 系統だけにする: primary `#4361ee`、hover 用の濃い青、選択状態用の淡い青。
  - 背景は白と薄いグレー(`#f6f7f9` 前後)。文字は濃いグレーと補助のグレーの 2 段階。罫線は 1 色。
  - 状態の色は error(赤)と warning(琥珀)の 2 色だけ。`--warning-color` が青になっている不整合もここで直す。
  - 特集の紫グラデーション(`#667eea`→`#764ba2`)と金色系は削除する。
- **装飾**
  - 次のものは使わない: グラデーション、`backdrop-filter`、`text-shadow`、常時ループするアニメーション、hover で浮かせる・拡大する動き、リップル、時間差で現れる演出。
  - 影は、ポップアップ(ダイアログ、トースト)の 1 種類だけにする。カードは罫線で区切る。
  - 角丸は 4px と 8px の 2 種類にする。丸ボタンなど形として必要な箇所だけ `50%` を使う。
  - 動きは色と透明度の `transition`(150ms)だけにする。`transition: all` は使わない。
  - `prefers-reduced-motion` に対応する。
- **文字**
  - フォントは Noto Sans JP の 400/500/700 をそのまま使う。読み込んでいない 600 の指定はなくす。
  - サイズは 12 / 14 / 16 / 20 / 24px の 5 段階にする。今は 22 種類ある。
- **間隔**: 既存の 4 / 8 / 16 / 24 / 32 / 48 の刻みを使い、px の直書きをしない。
- **ブレークポイント**: モバイルファーストで `min-width: 640px` と `min-width: 1024px` の 2 つだけにする。

### 画面ごとの変更
- **ヘッダー**
  - グラデーションの帯と、80px の丸いロゴをやめる。
  - 白地に左寄せのアプリ名と下罫線だけにする。
  - 検索カードがヘッダーに重なる配置(`margin-top:-24px`)をやめる。
- **検索欄**
  - 性別の選択はセグメント型の切り替えにする。
  - 季節は普通のチェックボックスにする。
  - 生成ボタンは単色にする。`fa-magic` のアイコンは外す。
- **特集キーワード**
  - 紫の背景、回転する光沢、ガラス風のボタンをやめる。
  - 罫線付きのボタンを並べ、選択中は淡い青の背景にする。
  - チェックマークとリップルが同じ疑似要素を取り合っている衝突も、ここで解消する。
- **使い方の折りたたみ、注釈(メンズ・季節未付与)**
  - 丸で囲んだアイコンをやめる。
  - 左に色の線を引いた注記ブロックにする。
- **カード**
  - グラデーションのヘッダー、光る「特集対応」バッジ、飾りのペンアイコンをやめる。
  - 欄ごとのアイコン(fa-heading など)を外し、文字のラベルだけにする。
- **エクスポートのダイアログ、トースト**
  - グラデーションのヘッダーと色付きの光彩をやめる。
- **フッター**: 1 行だけの控えめな表示にする。

### アイコン
- `base.html:9-11` の Font Awesome の読み込みを削除する。
- インライン SVG にするのは、コピー、チェック、閉じる、警告、性別の切り替えの記号(必要なら)の数個だけ。共通部品は `_macros.html` にマクロとして置く。
- `toast.js` の `icon` 引数(FA のクラス名を受け取っている)を廃止し、呼び出し元から外す。JS で FA の `<i>` を組み立てている約 16 か所を整理する。
  - 該当ファイル: `featured-keywords.js`、`generate.js`、`export.js`、`toast.js`、`template-card.js`、`clipboard.js`

### 文言の整理(利用者に見える変更。PR ② の詳細設計で一覧を出して合意する)
- 見出しが二重になっている(「生成結果」と「あなたのキーワードに最適化されたテンプレート」)ので、1 つにまとめる。
- 「スクレイピング」の表記を「データ取得」に変える。
- 「⭐」と「生成完了！」をやめ、平叙文にする。
- フッターの「All Rights Reserved.」は削除する。
- CSS のコメントにある「洗練された」などの言い回しは、書き直しで消える。

### CSS の書き直しの手順
1. 書き直す前に、375 / 768 / 1280px で全画面のスクリーンショットを撮っておく。状態は、初期表示、特集選択、ローディング、結果、エラー、ダイアログ。
2. 新しい `style.css` を、トークン → 基本要素 → 部品(画面の上から順)→ 状態 → `@media` の順に、1 ファイルで書く。
   - 目安は 1000 行以下。分割は指示がないのでしない。
   - 状態を表す新しいクラスには `is-` を付ける。既存の `.active` / `.show` などは JS が参照しているので、名前は変えない(CLAUDE.md の方針)。
3. 新しい CSS を書く前に、JS が `classList` で付け外ししているクラス名を grep で洗い出し、すべてにスタイルがあるか照合する。

### ドキュメント
- README の「既知の技術的負債」から CSS の節を削除し、デザインの基準を短く書く。
- CLAUDE.md の CSS の節と、`blue color theme` の記述を更新する。

## PR ③:使い勝手の改善
ブランチ: `feat/ui-ux-improvements`

### 結果一覧
- **ページ送りをやめる**
  - `template-list.js` のページ送り処理と 300ms の遅延、`index.html` の `.pagination` を削除する。
  - 画面幅に応じたグリッドで全件を描画する(PC は 3 列前後、スマホは 1 列)。
- **カード**
  - 左上に番号(#1〜)を付ける。
  - 欄ごとのコピーボタンを常に表示する。`aria-label` を付け、キーボードでフォーカスしたときに見えるようにする。
- **結果見出しの行**
  - 「N 件」「再生成」「全てコピー」「書き出し」を並べる。
  - 「再生成」は今の入力内容のまま `generate()` を呼ぶ。季節未付与の注記にも「再生成」ボタンを置く。
- **特集の表示**
  - 全カードに出している「特集対応」バッジをやめる。
  - 結果見出しの横に一度だけ「特集: ○○」と出す。
  - 出す条件は `GenerationOutcome.featured_info`。API の形は変えない。

### 待ち時間
- `progress.js` の疑似進捗(段階ごとの時間割り振りと creep 処理)を削除する。
- 代わりに次を表示する。
  - 動き続けるバー
  - 「生成中… N 秒経過」
  - 目安の文言「通常 20〜40 秒、混雑時は最大 2 分」
- 3 段階の表示も、時間で進めているだけで実際の進み具合と関係がないので削除する。
- 読み上げ対策として、`aria-live` には開始と終了の文言だけを流す。秒数のカウントは `aria-hidden` にする。
- **中止ボタン**
  - `api.js` の `requestJson` が外から `AbortSignal` を受け取れるようにし、タイムアウト用のシグナルとまとめる(`AbortSignal.any`)。
  - 中止したときは、エラーではなく「中止しました」と表示して元の状態に戻す。
  - サーバー側の処理は止まらない。仕様としてドキュメントに書く。
- **待っている間も前回の結果を残す**
  - `hideResults()` をやめ、前回の結果を薄く表示して操作できないようにする(`inert`)。
  - 成功したら差し替え、失敗や中止なら元に戻す。
  - 自動スクロールは、結果が表示されたときの 1 回だけにする。

### 通知
- `#copied-toast` と `showCopyToast()` を削除する。コピーは押したボタンの「✓ コピー済み」の表示(1.5 秒)だけで知らせる。「全てコピー」も同じにする。
- 次の通知を削除する。
  - 「特集キーワードを正常に読み込みました」
  - 生成成功のトースト(結果が表示されるので不要)
  - 選択を解除したときのトースト
- 特集の性別を自動で切り替えたときの通知は残す。`window.confirm` は、ユーザーが自分で性別に触れている場合だけ出す、今の挙動のままにする。
- 整理したあとに残る通知の種類と使い分けを、`toast.js` の先頭コメントの表に反映する。

### アクセシビリティ(上の変更に付随するものだけ)
- 性別のラジオに `:focus-visible` を付ける。
- エクスポートのダイアログで、開いたときに中へフォーカスを移し、閉じたら元のボタンに戻す。

### テストとドキュメント
- `tests/test_main.py` の `TestTemplateContext`(`maxlength="30"`、`0/30`、`（50文字以内）` などの文字列一致)が通ることを確認する。マークアップを変えて落ちた場合は、検証している意図(上限値が config から入ること)を保つように更新する。
- 応答の形のスナップショット(`test_main.py:105-163`)は API を変えないので、そのまま通るはず。
- CLAUDE.md の Frontend の節(通知の面が 5 つあること、`progress.js` の説明)を更新する。

## 確認方法(各 PR 共通)
1. `pytest` と `ruff check .`
2. `python run.py` で起動し、Playwright MCP で 375 / 768 / 1280px を確認する。
   - 初期表示
   - 性別の切り替え
   - 特集の選択と解除
   - 生成(実際に Gemini を呼ぶ)
   - 待っている間の表示と中止
   - 結果の表示、欄ごとのコピー、全てコピー、書き出し
   - エラー(キーワードが空のとき、通信を止めたとき)
3. コンソールにエラーがないこと。`dom.js` の起動時チェックで null の要素がないこと。
4. PR ② では、元の CSS のクラスと照合して、スタイルの当たっていないクラスがないこと。dark mode はもともと対応していないので対象外。
5. 書き直す前と後のスクリーンショットを PR に添付する。
